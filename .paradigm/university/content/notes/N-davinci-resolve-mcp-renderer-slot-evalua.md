## What it is

[`samuelgursky/davinci-resolve-mcp`](https://github.com/samuelgursky/davinci-resolve-mcp) (MIT, v2.224.2, single maintainer) is a local **stdio** MCP server that lets an AI agent drive **DaVinci Resolve Studio**. Two servers ship together:

- **Python server** (`src/`) — drives *live* Resolve via the official scripting API. 37 **compound** tools (each dispatches on an `action` param); a `--full` granular mode exposes ~377 one-per-operation tools.
- **Node server** (`resolve-advanced/`) — *offline* `.drp`/`.drt`/`.aaf` authoring + QC with no Resolve open.

No network listener by default, no telemetry, no obfuscation. Only outbound call is an opt-in GitHub version check. An npm bootstrapper (`bin/*.mjs`) launches a project-local Python venv; **there are no npm pre/postinstall hooks**, so `npm i` runs nothing.

## Why we care — the renderer slot

Atelier v2 is **not a renderer** (`docs/v2-hyperframes-migration.md`): it is the brand + direction + asset + voice layer that *feeds* a renderer. The mainline renderer is **Hyperframes** (HTML/CSS, seek-driven capture → ffmpeg). This tool is being evaluated as an **alternative backend in the same slot** — a mature timeline NLE instead of a web renderer. Iris (the render-driver) owns the comparison. Skill bundle: `.paradigm/personas/iris/skills/resolve-backend/`.

The question the evaluation answers: **does a real NLE's timeline + finishing pipeline earn its weight over the HTML/CSS renderer for agent-driven, brand-cascaded short-form?**

## Security audit — verdict: SAFE-WITH-CAVEATS

A four-part source audit (2026-09-11) found a legitimate, security-*aware* project. Strengths: no shell (`shell=True` nowhere; all subprocess is argv-array), no `eval`/`exec` on dynamic input, careful config backup-and-merge in the installer, a genuinely good bridge auth model (HMAC-SHA256 over canonical JSON, constant-time compare, secret never on the wire, timestamp+nonce replay defense, loopback-only), and textbook secret hygiene (`token_urlsafe(32)`, `0o600`, refuses loose-perm `bridge.json`).

**The caveats that shape how Iris must use it:**

1. **Unconfined filesystem paths (biggest).** Neither the main server nor the bridge's generic `op_call` confines agent-supplied import/export/render/delete paths — a tool call can read/write/delete anywhere the OS user can. **Rule: only ever pass paths derived from the current atelier project; never echo a path from untrusted content (transcript, filename, web result) into a path arg.**
2. **`safe_mode` ships OFF** — nothing destructive is gated by default; turn it on. Even on, ~80/108 destructive actions match no risk rule, and the `confirm_token` is a self-serve mint→resubmit echo (no human-in-the-loop). These guard accidents, not a misdirected instruction — so Iris confirms intent herself.
3. **Auto-update re-exec.** The installer's opt-in `auto` policy `git pull`s then `os.execv`-restarts unattended — keep it `prompt`/`never`, especially on a fork with a repointed remote.
4. **PATH trust.** Interpreters/tools (`python3`, `ffmpeg`, `unzip`, `pg_dump`) resolve by bare name — a poisoned PATH is the main unintended-exec route.

## Fork-readiness (if we fork)

- `src/server.py` is a **1.5MB / 32.8k-line god-file** — but only 37 tools; the bulk is 658 inlined helpers. The clean decomposition already exists in-repo as `src/granular/` (11 domain modules) — mirror it.
- `analysis_dashboard.py` (717KB) embeds a whole HTML/JS frontend as Python heredocs → externalize.
- Hybrid Python+Node doubles the surface; `package.json` dep lists are duplicated. `resolve-advanced/vendor/` (3.3MB) is **mislabeled** — it is first-party format libs, not third-party.
- Shipped cruft: a 738KB CHANGELOG and 7 byte-identical *generated* agent-rule trees (regenerated by a script — don't hand-edit) are in the npm `files:`.
- Strengths to keep: 250 offline pytest files that stub Resolve (run without the app) + real CI with drift guards; `api_truth.py` is intentional drift-guarded data-as-code.

Priority hardening for a fork: (1) add path-root confinement + default `safe_mode` on; (2) retarget update-check/repo URLs; then the refactors.

## The atelier → Resolve mapping (how the pipeline lands)

| Atelier | Resolve | Tool |
|---|---|---|
| Project variant | Resolve project + one timeline | `project_manager.create`, `media_pool.create_timeline` |
| Media + pack assets | media-pool clips | `media_storage`, `media_pool` |
| STORYBOARD beat (timing window) | timeline item at a **record-frame** range | `media_pool.create_timeline_from_clips(clip_infos)` |
| Brand fps / frame size | project settings | `project_settings` |
| Transcript segments | subtitle track **or** Fusion `Text+` | `timeline` subtitle actions / `fusion_comp` |
| Brand look / palette | color page / CDL | `color_grade_workflow`, `timeline_item_color` |
| Final deliverable | render job + QC | `render_presets` → `delivery_workflow` → `render.start` → `verify_output` |

Key insight: **Resolve counts in frames at a project fps**, so every "at Xs for Ys" beat becomes a frame range (`round(s*fps)`). And Resolve reports a render `Complete` even when the file is near-empty — so `render.verify_output` (ffprobe vs timeline extent) is mandatory, the direct analog of the Hyperframes "file suspiciously small" check.

## Free vs Studio (from the MCP standpoint)

Two layers of limitation. **The MCP detects the edition** — `resolve_control(action="is_studio")` (→ `IsStudio()`) — and **degrades gracefully**: Studio-only calls return `success:false` with Resolve's own reason, or surface as `capability_gaps`. Free never crashes; gated tools just refuse with an explanation. Have Iris call `is_studio` as the first probe so a run knows which half of the surface is live.

**Layer 1 — access (can you connect at all):**

| Setup | Works? | How |
|---|---|---|
| Studio (paid), any recent version | ✅ | External scripting directly (baseline 19.1.3; tested through 21.x) |
| **Free ≤ 21.0.x** | ✅ | In-app bridge only (validated on free **21.0.3.7**) |
| **Free 21.1+** | ❌ | Resolve 21.1 moved Python scripting to Studio — free Scripts menu no longer lists `.py`; bridge is dead |

**⚠ Version requirement (the thing that bites):** a *fresh* Blackmagic download today is well past 21.1, which **will not work on free**. For the free path you must deliberately source an **older ≤ 21.0.x** installer (21.0.3 is the known-good build). Otherwise use Studio, where version is not the constraint.

**Layer 2 — capability once connected.**

Works on free (the core renderer-slot plumbing): `project_manager`/`project_settings`, `media_storage`/`media_pool`/import, `create_timeline_from_clips`, `timeline`/`edit_engine`/`timeline_item`, markers/takes, subtitles, `fusion_comp`/`Text+` titles, basic color (CDL, node graph, `safe_apply_drx`), and `render`/`delivery_workflow`/`verify_output` **within free's export ceiling**.

Studio-gated → the MCP tool refuses on free:

| Capability | Surface |
|---|---|
| Neural Engine AI: Magic Mask, Smart Reframe, Object Removal, Face Refinement, Detect Scene Cuts | `timeline_item_color`, `timeline_ai` |
| AI Extras pack: IntelliSearch, Slate, `GenerateSpeech`, Motion Deblur (report `success:false` if pack absent, even on Studio) | `media_analysis`, `timeline_ai` |
| Auto-transcription / speaker detection (Resolve 21 AI) — **not needed; atelier runs whisper upstream** | `media_analysis` |
| Voice Isolation, Dialogue Leveler (Fairlight AI) | audio actions |
| Noise Reduction (temporal/spatial), HDR / Dolby Vision, film grain, most Resolve FX | color tools, `AnalyzeDolbyVision` |
| Delivery ceiling: free caps at **UHD/4K max**, no 10-bit HEVC, narrower codec set | `render` presets |
| Multi-user collaboration, remote/network rendering, Super Scale, stereo 3D | `project_manager` collab, render nodes |

**Punchline for the evaluation:** the core pipeline (project → media pool → beats → captions/`Text+` → 1080p H.264 render + verify) runs on **free ≤ 21.0.x** — enough to prove the integration. But the gated features (Smart Reframe for multi-aspect, Voice Isolation / Dialogue Leveler for clean VO, NR, HDR, >4K/10-bit) are **exactly the finishing reasons to pick Resolve over Hyperframes**. Free validates the plumbing; **Studio is where the argument for this backend actually lives.**

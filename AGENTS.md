# Atelier — AI Agent Instructions

## What Is Atelier?

Atelier is an **AI-native animation engine**. It defines motion graphics as declarative YAML documents (`.atelier` files) containing visual layers, named animation states, and frame-by-frame property interpolation instructions called **deltas**. The primary authoring path is through 27 MCP tools — an AI agent can create, edit, preview, and export animations without writing code.

For the complete AI authoring reference, see **[docs/ai-agent-guide.md](docs/ai-agent-guide.md)**.

## Packages (8)

| Package | What It Does |
|---------|-------------|
| `@atelier/types` | 44 TypeScript type definitions (zero runtime) |
| `@atelier/math` | Interpolation engine: easing, spring physics, color lerp |
| `@atelier/schema` | Zod validation + YAML parse/serialize |
| `@atelier/core` | Animation engine: `resolveFrame`, `DocumentBuilder`, `StateMachine`, templates, presets |
| `@atelier/canvas` | Canvas 2D renderer: shapes, text, images, gradients, shadows, stroke trim |
| `@atelier/studio` | Browser editor widget + MP4/WebM/GIF export (WebCodecs) |
| `@atelier/mcp` | MCP server (27 tools) for AI authoring |
| `@atelier/cli` | CLI: `validate`, `info`, `still`, `render` (MP4/GIF via FFmpeg) |

## Key Concepts

- **Layers** define what is visible (shapes, text, images, groups, refs)
- **States** define time segments with a frame duration
- **Deltas** animate a single property of a single layer over a frame range within a state
- **22 animatable properties**: position, size, opacity, rotation, scale, anchor point, corner radius, fill/stroke colors, stroke width, stroke trim (start/end), font size, text color, shadow (color/blur/offsetX/offsetY)
- **5 easing types**: linear, cubic-bezier, ease presets (in/out/in-out), spring physics, step
- **No-overlap rule**: two deltas on the same layer + same property cannot overlap in time
- **Hold-after-end**: after a delta's range ends, its `to` value persists

## Commit Messages

Use v2 symbols in commits for history tracking:

### Format
```
type(#primary-symbol): short description

- Detail with #component references
- Gate changes: ^gate-name
- Signals emitted: !signal-name

Symbols: #symbol-a, #symbol-b, !signal-c
```

### Convention
- **Subject**: `type(#symbol): description` — primary symbol in parens
- **Body**: Reference affected symbols with prefixes (# $ ^ ! ~)
- **Trailer**: `Symbols: #a, #b, !c` — machine-readable list of ALL affected symbols
- The `Symbols:` trailer is parsed by the post-commit hook for automatic history capture

### Examples
```
feat(#payment-form): add Apple Pay support

- Add #apple-pay-button component
- Update $checkout-flow with new payment step
- Emit !payment-method-added signal
- Gate: ^authenticated required

Symbols: #payment-form, #apple-pay-button, $checkout-flow, !payment-method-added
```

## Session Recovery & Handoff

### Session Start (EVERY new session)

Call `paradigm_session_recover` to load previous session breadcrumbs.
Returns: symbols modified, files explored, recent actions, and suggestions.

### Context Monitoring

Call `paradigm_context_check` every 10-15 tool calls to track context usage.

| Usage | Recommendation | Action |
|-------|----------------|--------|
| <50% | continue | Keep working |
| 50-70% | consider-handoff | Plan a stopping point |
| 70-85% | handoff-recommended | Prepare handoff soon |
| >85% | handoff-urgent | Handoff after current task |

### Handoff Process

1. Call `paradigm_handoff_prepare` with summary, next steps, and target agent
2. User runs: `paradigm team handoff --to <agent> --summary "..."`
3. New session accepts: `paradigm team accept <handoff-id>`
